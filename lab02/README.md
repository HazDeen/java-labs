## Описание инвариантов сущностей

### 1. Инварианты BankAccount (подготовительная часть)
- **Баланс**: `balance >= 0`. Баланс никогда не может быть отрицательным (проверяется в конструкторе).
- **Пополнение (`deposit`)**: принимается только положительная сумма (`amount > 0`), итоговый баланс не превышает `Integer.MAX_VALUE`. При превышении этого предела операция отклоняется без изменения баланса.
- **Списание (`withdraw`)**: сумма списания строго больше нуля (`amount > 0`) и не может превышать текущий остаток (`amount <= balance`).
- **Инкапсуляция**: поле `balance` является `private`; отсутствуют прямые сеттеры, изменение состояния происходит только через бизнес-операции.

### 2. Инварианты DataSample (вариант ИСИИ)
- **Идентификатор (`id`)**: хранится как неизменяемый `SampleId`. Его строковое значение не равно `null`, не пустое и не состоит только из пробелов (`!value.isBlank()`). Ссылка на идентификатор неизменяема (`final`). Конструктор `DataSample` по-прежнему принимает строку, а `getId()` возвращает строку.
- **Метка класса (`label`)**: не равна `null`, не пустая и не состоит только из пробелов (`!label.isBlank()`). Значение неизменяемо (`final`).
- **Статус (`status`)**: не равен `null`. Изменяется только через специализированный метод `changeStatus(SampleStatus newStatus)`.
- **Массив признаков (`features`)**:
  - не равен `null`;
  - не пустой (`features.length > 0`);
  - содержит только валидные конечные вещественные числа (без `NaN` и `Infinity`).
- **Защитное копирование (Defensive Copying)**:
  - массив копируется при получении в конструкторе (`Arrays.copyOf`), чтобы внешняя мутация массива не повлияла на внутреннее состояние объекта;
  - метод `getFeatures()` возвращает копию внутреннего массива, предотвращая неконтролируемое изменение состояния снаружи.

`averageFeature()` вычисляет среднее постепенно, без накопления суммы, которая могла бы переполниться. Если разность очередного признака и текущего среднего переполняется, используется эквивалентная формула с весами. Например, среднее двух значений `Double.MAX_VALUE` остается `Double.MAX_VALUE`, а не бесконечностью. Как и другие вычисления с `double`, результат может иметь погрешность округления.

## Дополнительная часть

### Неизменяемый идентификатор `SampleId`

`SampleId` — record с единственным компонентом `String value`. Конструктор запрещает `null`, пустую строку и строку только из пробельных символов. Значение сохраняется как передано: пробелы вокруг непустого идентификатора автоматически не удаляются.

Record автоматически создает закрытое поле `private final`, метод чтения `value()`, а также `equals`, `hashCode` и `toString`. Record нельзя наследовать, методов изменения значения нет. Поскольку `String` тоже неизменяем, содержимое идентификатора нельзя изменить после создания.

Идентификатор представляет **значение**: два отдельно созданных `new SampleId("sample-01")` равны через `equals`, потому что их текст совпадает. Важно значение, а не то, являются ли они одним объектом в памяти. `==` для этих двух объектов проверяет ссылки и не заменяет `equals`. Равенство идентификаторов не означает автоматического равенства самих объектов `DataSample`.

`DataSample` хранит `SampleId` внутри. `getId()` возвращает текст для совместимости с обязательным заданием, а `getSampleId()` возвращает сам неизменяемый идентификатор. Защитная копия `SampleId` не нужна: изменить его нельзя.

Пример через Тетрис: `SampleId("piece-17")` — номер конкретной фигуры, а `label = "T"` — ее вид. Перемещение фигуры не меняет номер. Два объекта идентификатора с текстом `"piece-17"` обозначают один и тот же номер.

### Нормализация признаков без изменения объекта

`normalizedFeatures()` находит минимум и максимум и возвращает **новый массив**. Для каждого элемента вычисляется `(значение - минимум) / (максимум - минимум)`.

Пример: `[10, 20, 30]` превращается в `[0, 0.5, 1]`. Минимум становится нулем, максимум — единицей. Порядок элементов сохраняется; отрицательные исходные числа допустимы.

Если все значения одинаковые, включая массив из одного элемента, возвращаются нули: разность максимума и минимума равна нулю, и обычная формула делила бы на ноль. Маленькая ненулевая разность нормализуется обычным способом. Если разность очень больших конечных чисел переполняет `double`, вычисление выполняется в масштабе, уменьшенном вдвое.

Метод не меняет исходные признаки, идентификатор, метку или статус. Изменение возвращенного массива тоже не влияет на объект. Нормализация не переводит статус автоматически в `PROCESSED` или `READY`.

В этой работе нормализуются числа **одного образца**. Это учебная операция; она не вычисляет общие масштабы по всем образцам набора данных.

```java
DataSample sample = new DataSample(
        "piece-17", "T", SampleStatus.RAW, new double[]{10.0, 20.0, 30.0});

SampleId id = sample.getSampleId();
boolean sameValue = id.equals(new SampleId("piece-17")); // true
double[] normalized = sample.normalizedFeatures();      // [0.0, 0.5, 1.0]
double[] original = sample.getFeatures();               // [10.0, 20.0, 30.0]
SampleStatus status = sample.getStatus();                // RAW
```

Тесты дополнительной части проверяют допустимость идентификатора, равенство по значению и согласованность `hashCode`, использование идентификатора в `DataSample`, обычную нормализацию, одинаковые числа, один элемент, отрицательные и неупорядоченные числа, очень маленький и очень большой диапазон, а также независимость результата от исходного объекта.
