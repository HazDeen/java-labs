## Разбор варианта «Инженерия ИИ»

Отдельный `DataSample` не нужен: указанный в условии интерфейс работает прямо с `double[]`.

### Как работает нормализация

Для `[10, 20, 30]`:

- Min-Max: min = 10, max = 30; результат `[0, 0.5, 1]`.
- Центрирование: среднее = 20; результат `[-10, 0, 10]`.

Центрирование не ограничивает значения диапазоном `[0, 1]`.
Для поиска границ используется цикл `for-each`, для записи результата — индексный
цикл `for`. `new double[values.length]` создаёт отдельный массив той же длины.
Записей в `values[i]` нет, поэтому исходные признаки сохраняются.
Оба алгоритма работают за O(n) и используют O(n) дополнительной памяти.

Среднее вычисляется постепенно: `mean += (value - mean) / count`.
Это позволяет не накапливать сумму, которая может переполнить `double`.
В коде отдельно обработана ситуация, когда переполняется сама разность.
Min-Max при переполнении `max - min` использует половинный масштаб.
Эти проверки связаны с ограниченным диапазоном чисел типа `double`.

### Какие решения приняты для граничных случаев

Условие не определяет все ошибки входных данных; здесь выбран такой контракт:

- `null` и пустой вектор запрещены: `IllegalArgumentException`.
- `NaN` и бесконечные элементы запрещены тем же исключением.
- Одинаковые значения и один элемент дают новый массив нулей.
- Если результат центрирования не помещается в конечный `double`,
  выбрасывается `ArithmeticException`.
- Цена должна быть конечной и неотрицательной; процент — конечным от 0 до 100.
- Калькулятор и обработчик не принимают `null` вместо зависимости.

### Где здесь Java и полиморфизм

```java
NormalizationStrategy strategy = new MinMaxNormalization();
FeatureProcessor processor = new FeatureProcessor(strategy);
double[] result = processor.process(new double[]{10, 20, 30});
```

Тип ссылки `strategy` — интерфейс `NormalizationStrategy`, фактический тип
объекта — `MinMaxNormalization`. Интерфейс определяет доступный метод,
а фактический класс определяет, какая реализация `normalize` выполнится.

Для центрирования передай `new MeanCenteringNormalization()` в конструктор
нового обработчика. Код `FeatureProcessor` менять не требуется.
`final` у поля запрещает заменять ссылку внутри уже созданного обработчика;
условие не требует отдельного setter для переключения стратегии.

- `implements` — класс обязуется реализовать методы интерфейса.
- `@Override` — компилятор проверяет переопределение метода.
- `private` — поле доступно только внутри своего класса.
- `this.strategy` — поле текущего объекта; `strategy` — параметр конструктора.
- `return` — возвращает результат и завершает метод.
- `throw` — завершает обычное выполнение с исключением.
- Композиция — обработчик содержит ссылку на объект стратегии.
- Внедрение зависимости — нужный объект передаётся обработчику снаружи.

Переопределение: разные классы реализуют одну сигнатуру `normalize(double[])`.
Перегрузка: методы имеют одно имя, но разные списки параметров.
Здесь используется переопределение.

### Что проверяют тесты

В `DiscountPolicyTest` проверяются цены, проценты, границы и замена политики.
В `NormalizationStrategyTest` — обе формулы, отрицательные и одинаковые значения,
одиночный элемент, неверный ввод, сохранение исходного массива, числовые границы
и замена стратегии в обработчике. Отдельный тест с третьей тестовой реализацией
показывает, что обработчик работает с контрактом интерфейса.

Тестовые методы не принимают параметров и возвращают `void`; JUnit запускает
методы с `@Test`. `assertArrayEquals` сравнивает элементы с погрешностью `1e-9`,
`assertNotSame` проверяет разные ссылки, `assertThrows` — нужное исключение.
Лямбда `() -> ...` в `assertThrows` передаёт JUnit действие для проверки.
Анонимный класс в тесте третьей реализации создаёт объект интерфейса с собственным
телом метода; это только демонстрация расширяемости в тесте.
